# SciSpark · 科研创新助手

> 把「读论文 → 梳理逻辑 → 找空白 → 对话收敛 → 查重 → 写提案」串成一条闭环的本地工具。
> 界面支持中英文切换，调研结果也可以选择中文或英文输出；数据只存在你自己电脑上。

[English](README.en.md) | 中文

本项目基于 [CoQuest](https://github.com/yiren-liu/coquest) 修改而来，详见[来源声明](#来源声明)。

![论文库](docs/screenshots/papers.png)

## 这是什么

做研究最耗时的不是读某一篇论文，而是**在一堆论文之间建立联系，并判断哪里还没人做过**。
SciSpark 把这件事拆成几个模块，每一步都有对应的界面和产物：

| 模块 | 你得到什么 |
|---|---|
| **论文库** | 输入主题，自动从 arXiv / OpenAlex 检索、去重、排序，逐篇抽取中文结构化卡片（问题 / 方法 / 数据集 / 发现 / 局限 / 关键断言） |
| **本地论文** | 读你自己文件夹里的 PDF，抽观点 → 跨篇大纲 → 创新点讨论 |
| **论文图谱** | 把论文连成三层图（引用耦合 / 语义 / 概念），再从连接方式里挖「研究空白」 |
| **共创对话 / 研究脑图** | 和 AI 一起把模糊方向收敛成可执行的研究问题，AI 的思考全程可见、可质疑 |
| **创新点 / 进展扫描** | 想法两两盲评排 Elo、生成研究提案；按时间窗扫「这段时间发生了什么」 |

模型用 DeepSeek，一轮完整流程（200 篇 → 10 个想法 → 20 轮对话）约 **¥3~5**。

## 快速开始

### 你需要什么

- **什么都不用装**：发布包里自带 Python 运行环境和全部依赖（macOS / Windows 各一套），
  **不用装 Python、不用装 Docker、不用联网下载**
- 一个 [DeepSeek API Key](https://platform.deepseek.com/)（很便宜，几块钱能用很久）
  —— 只有点「调研」「理解」这类按钮才会用到它

### 三步启动

1. 解压发布包（或者 `git clone` 本仓库）
2. **双击「启动」**
   - Windows：`启动.bat`
   - macOS：`启动.command`（**第一次**如果弹「未打开 / Apple 无法验证」，
     把这个文件拖进「终端」窗口按回车即可，详见下方 FAQ）
3. 浏览器会自动打开 `http://localhost:8000`；进「设置」填 API Key → 点「测试连接」

> **不需要安装，也没有安装界面**：程序就装在你解压出来的这个文件夹里。
> 双击「启动」后它会自动用**包内自带的 Python 运行时**展开依赖（都在 `vendor/` 里，
> 不碰系统环境、**不下载任何东西**），然后铺演示数据、启动服务、打开浏览器。
> **删掉整个文件夹就等于完全卸载**。
>
> 只有两种情况下才会改用别的路子：这台电脑之前用 Docker 装过（镜像还在，沿用旧方式）；
> 或者你手上的是**轻量包**（`--no-vendor` 打的，没有 `vendor/`）——那种包会在第一次启动时
> 用系统 Python 建 `.venv` 并从 PyPI 下载依赖。
> 想强制指定：`python3 tools/launcher.py --native` 或 `--docker`。

> **端口会自动挑**：默认用 8000。如果 8000 被别的软件占用了（很常见，比如打印服务、
> 各种开发服务器），会自动换到 8001、8002……，打开的网页地址也是对的，你什么都不用做。
> 以前这里会把别人的网页误当成 SciSpark 打开，现在会先确认「这个端口上跑的到底是不是本程序」。

> **第一次启动约 30 秒**：把包里自带的依赖展开到 `vendor/<平台>/site-packages`，
> 全程在本机进行、**不联网、不下载**。之后启动都是十几秒。
> 代价是压缩包比较大（约 130 MB，因为里面装了两套平台的运行时）；
> 换台电脑时把这个 zip 拷过去解压即可，**不用再等几分钟下载**。

> **Docker 资源**（仅 Docker 模式）：推荐 4 核 / 6 GB。不够也能启动（只是第一次会慢一些），
> 启动器会提示你怎么调：Docker Desktop → 设置（齿轮）→ Resources → 调 CPU / Memory。

### 关闭

三种方式，任选：

- 点界面左下角的 **「关闭 SciSpark」**
- 双击 **「停止」** 脚本
- 原生模式：在终端按 `Ctrl+C`

数据都在 `data/` 目录，关掉不会丢。

### 首次启动会做什么

- 生成 `.env`（把 `HOST_HOME_DIR` 填成你的用户目录，供「选择文件夹」用）
- 把 `demo/app.db` 铺到 `data/app.db` —— 里面有一个演示项目「RAG 评测方法」，
  76 篇论文、图谱、空白、脑图、对话、扫描报告都是现成的，可以先点着看再建自己的项目

## 功能详解

### 一、论文库

1. 新建项目 → 填研究主题
2. 进「论文库」→「开始调研」，可以设置：
   - **保留篇数**（10~150，越多越慢越贵）
   - **发表时间范围**：年 / 月 / 日分开填，或点「近 1 年 / 3 年 / 5 年」
   - **发表渠道偏好**：优先期刊列表（如 `Nature、ACL、NeurIPS`）、只要正式发表、被引 ≥ N 次优先
   - **这一批叫什么**：留空就用检索主题当名字，之后还能改
3. 结果表可以按期刊筛选（点任意一格即可只看该期刊），也可以按调研批次筛选

> **关于调研批次**：每调研一个新方向，都会在论文库里开一个新块。默认按批次分组显示，
> 每块一个标题条（批次名 + 检索主题 + 时间 + 篇数）。点标题可以直接改名字，
> 右边的「只看这批」可以单独看，「删除」会把这一批连同它的论文一起删掉。
>
> 为什么这么设计：连着调研「RAG 评测」和「引用归因」之后，200 篇论文混在一张表里
> 根本分不清哪个是哪个方向来的。一篇论文只属于**首次入库**的那一批——新批次再检索到
> 它不会改归属，否则「这批新增了什么」就说不清了。升级前的老论文统一归到「早期导入」。

> **关于期刊偏好**：OpenAlex 和 arXiv 都不提供影响因子，所以这里用的是三个能拿到的信号
> —— 期刊名匹配、是否正式发表、被引次数。而且它们只是**排序权重，不是硬过滤**：
> 刚发表的好论文被引一定是 0，一刀切会漏掉最新工作。

> **关于「已跳过」**：结构化理解需要摘要。拿不到摘要的论文（arXiv 元数据缺失、
> OpenAlex 没收录 abstract）会标成「已跳过」并写明原因，不会无声地挂在「待理解」上。
> 标题栏的「重试 N 篇」可以把它们重置后重跑一次。

### 二、本地论文

1. 点「选择文件夹」，在弹窗里点选你放论文的目录（支持 PDF / DOCX / MD / TXT）
2. 勾选文件 →「导入并抽取观点」
3. 三个页签：
   - **已导入**：每篇的观点数、核心立场、可延伸方向
   - **大纲**：按逻辑（不是按论文）组织的跨篇结构，标出分歧与空白
   - **创新点讨论**：候选创新点 + 为什么新 + 怎么做 + 最大风险 + 最小验证实验，每条都能「查重」

> 文件夹选择器背后是把你的用户目录只读挂进容器，界面显示的路径和 Finder / 资源管理器一致。
> macOS 的「文稿 / 桌面」默认不给 Docker 访问权限，会在列表里显示成灰色「未授权」——
> 要用的话去 系统设置 → 隐私与安全性 → 文件与文件夹 → Docker，勾上对应目录。

### 三、论文图谱与空白

![论文图谱](docs/screenshots/graph.png)

三层关系，全部本地计算、**零 API 费用**：

| 层 | 含义 | 为什么需要 |
|---|---|---|
| 引用耦合 | 共同引用同一批工作 | 同一课题的论文常常互不引用（平行工作），但「引用的祖宗」高度重合 |
| 语义相近 | 标题 + 摘要 + 结构化理解的 TF-IDF 余弦 | 看字面内容 |
| 共享概念 | 结构化抽取出的概念重叠（IDF 加权） | 看问题结构 |

交互：拖拽平移、滚轮缩放（只缩放画布，不会把网页放大）、放大镜、缩放比例可直接输入。

「研究空白」页签用四种策略挖候选，再让 AI 判断真假：

![研究空白](docs/screenshots/gaps.png)

- **局限聚类**：多篇论文反复提到同一类局限
- **结论冲突**：两篇论文的结论互相打架
- **概念组合**：两个各自成熟、从未同时出现的方向
- **方法迁移**：把 A 的方法搬到 B 的问题上

判定结果是三档：**真空白 / 证据不足 / 已有人做**。第三档同样有价值——
它说明模型在做判断题，而不是顺着候选说好。

### 四、共创对话

![共创对话](docs/screenshots/chat.png)

左边聊，右边问题树会跟着长。每轮产出不只是回复，还有树上的新节点。

阶段由状态机管（发散 → 收敛 → 定稿 → 已定），**每轮最多前进一步**——
防的是模型一轮就宣布收敛，那是这类工具最常见的失败模式。

### 五、研究脑图

![研究脑图](docs/screenshots/mindmap.png)

画布优先：你自己加节点、拖位置、改文字，AI 只在你指的地方展开。

- 「AI 给几个方向」→ 从根节点长出 3~4 个可证伪的子问题
- 指着任意节点 →「让 AI 拆成子问题」或「从这里出创新点」
- 每个 AI 节点都挂着「为什么这么拆」和证据论文

### 六、进展扫描

![进展扫描](docs/screenshots/scan.png)

**默认关闭**，想用时再打开。选一个时间窗（近一周 / 一月 / 三月 / 半年 / 一年，或自定义），
扫这段时间的新论文，出一份**判断**而不是摘要堆叠：

> RAG 幻觉检测进入方法论反思期：组件组合收益衰减、指标伪影被揭示，评估正向证据级与鲁棒性转向。

提示词里明确要求：如果这批论文只是换数据集刷点，就直接说「没有突破性进展」。

### 七、创新点与提案

想法两两盲评排 Elo（每场随机决定谁先出现，避免系统性偏向 A），
点任意一行可以看详情、生成 800~1400 字的研究提案（可复制或下载 `.md`）。

## 常见问题

**Q：一定要装 Docker 吗？**
不用。没有 Docker 会自动走原生模式（需要 Python 3.10+，首次会建 `.venv` 装依赖，约 1~3 分钟）。

**Q：启动时看到在下载东西？**
只有第一次（或你主动 `--rebuild`）会下载：Docker 基础镜像、npm 包、pip 包。
之后启动是十几秒，不会重复下载。

**Q：数据存在哪？会上传吗？**
全部在本地 `data/app.db`（SQLite）。只有你点「调研」「理解」这类按钮时，
论文的标题和摘要会发给 DeepSeek API；其余全在本地算。

**Q：端口 8000 被占用？**
不用管。启动器会先确认 8000 上跑的是不是本程序，不是的话自动换到 8001、8002……，
并在窗口里告诉你实际地址。想固定端口：`APP_PORT=8010 python3 tools/launcher.py`。

**Q：论文理解成「已跳过」怎么办？**
大概率是拿不到摘要（arXiv 元数据缺失 / OpenAlex 没收录）。详情抽屉里会写明具体原因。
点「重试 N 篇」会重跑一次，但如果确实没有摘要，仍然会跳过——这是正确行为。

**Q：支持哪些系统？**
macOS 和 Windows 10 以上。Linux 也可以，用 `python3 tools/launcher.py`。

**Q：能多人共用吗？**
不建议。默认只监听 `127.0.0.1`，是单机工具。

**Q：Windows 上启动报 `the path "E:\..." is not shared from the host`？**
这是 Windows 版 Docker 的磁盘授权限制——它只允许访问你明确授权的磁盘。两个办法：

1. Docker Desktop → 右上角齿轮（Settings）→ Resources → **File Sharing** → 添加项目所在的盘（比如 `E:\`）→ 点 **Apply & Restart**
2. 更省事：把整个 `scispark` 文件夹移到 `C:\Users\你的用户名\` 下面再启动（用户目录默认已授权）

数据不会丢，它就在 `data/` 里，跟着文件夹一起走。

**Q：macOS 双击「启动.command」提示"未打开 / Apple 无法验证"？**

这是 macOS 对**所有未经 Apple 付费签名**的程序的统一拦截，不是这个软件要什么隐私权限。
从 macOS 15 起 Apple 收紧了「右键 → 打开」的老办法，对脚本类文件经常直接弹只有［完成］的框，
所以别再试右键了。**最可靠的一次性做法**：

1. `Command + 空格` → 输入「终端」→ 回车
2. 把「启动.command」**拖进终端窗口**（路径会自动填好，不用打字）
3. 按回车

脚本会正常运行，并顺手清掉整个文件夹的隔离标记 —— 之后「启动」「停止」双击都正常，
不会再弹任何框。也可以直接在终端里跑：

```bash
xattr -dr com.apple.quarantine /路径/scispark-1.0.0
```

（`xattr` 是 macOS 自带命令，只是去掉"从网上下载"的标记，不装东西、不改系统设置。）

系统设置里的「仍要打开」对 `.app` 有效，但对 `.command` 脚本常常**根本不出现这个按钮**，
所以不作为首选。

## 技术栈

| 层 | 技术 |
|---|---|
| 后端 | Python 3.12 + FastAPI + uvicorn |
| 数据库 | SQLite（WAL）+ FTS5，手写 SQL，无 ORM |
| 前端 | React 19 + Vite + TypeScript + Tailwind 4 + TanStack Query |
| 画布 | 自写力导向布局 / 树布局 + SVG（无第三方图库） |
| 检索 | arXiv + OpenAlex，BM25 粗排 + LLM 精排 |
| 部署 | Docker 单容器（FastAPI 直接托管前端静态文件），或原生 Python |

设计上几个刻意的选择：

- **不用 embedding**：DeepSeek 没有 embedding 接口，所以走 FTS5 BM25 + 查询扩展 + LLM 精排，
  语义层用 TF-IDF。60~200 篇的规模足够稳。
- **不引图库**：图谱和脑图都是几十到几百个节点，自写布局 + SVG 反而更可控
  （固定种子保证布局可复现，同一张图每次打开位置一致）。
- **LLM 只做判断题**：找空白、查重这类任务，先把候选压到十几条、把证据摆在模型面前，
  它只需要判断真假，幻觉空间小很多，成本也只有一次调用。

交互模型参考了 [CoQuest (CHI'24)](https://arxiv.org/abs/2310.06155) 的「问题树 + AI 思考外显 + 证据联动」，
代码全部重写（CoQuest 是学术实验原型，依赖老版本 AutoGPT 和 pickle 会话，无法直接复用）。

## 数据与运行环境存在哪

| 内容 | 位置 | 大小 | 说明 |
|---|---|---|---|
| 你的数据（论文、对话、图谱…） | `data/app.db`（**项目目录内**） | 几 MB | 备份这一个文件就够了 |
| 前端静态文件 | `frontend/dist/`（项目目录内） | 几百 KB | 构建产物 |
| 运行环境（Python + 依赖） | Docker 的虚拟磁盘，**不在项目目录** | 约 700 MB | Docker 架构限制，无法放到项目里 |

**为什么运行环境不在项目目录**：Docker 镜像必须由 Docker 自己管理（存在虚拟磁盘里），不能像普通文件一样放到任意文件夹。这是 Docker 的设计，所有用 Docker 的软件都这样。

**想释放空间**：

```bash
python3 tools/launcher.py --clean    # 删除容器和镜像（约 700 MB），data/ 不动
```

下次启动会重新下载环境（约 1~2 分钟）。

**如果希望所有依赖都在项目里**：用原生模式 `python3 tools/launcher.py --native`，Python 依赖会装进项目内的 `.venv/`（需要电脑有 Python 3.10+）。

## 与 CoQuest 的区别

CoQuest 是一篇 CHI 论文的**配套系统**，用来做「研究问题共创」的用户研究；SciSpark 是把它那套交互思想
做成一个**能日常用的完整工具**。代码是重写的，不是 fork。

| 维度 | CoQuest（原项目） | SciSpark |
|---|---|---|
| 定位 | SIGCHI 2024 论文配套原型，服务于受控用户实验 | 日常可用的全流程工具：调研 → 图谱 → 收敛 → 提案 |
| 后端 | 内嵌 AutoGPT 分支（`backend/autogpt/`）+ `openai==0.27.2`，Pinecone、Redis、Selenium、gTTS 语音 | FastAPI + SQLite（WAL）+ FTS5，手写 SQL 无 ORM；进程内异步任务队列，无外部中间件 |
| 前端 | CRA（react-scripts）+ Chakra UI + MUI + Material Tailwind + reactflow + d3 | React 19 + Vite + TS + Tailwind 4 + TanStack Query + Zustand |
| 模型 | 需配置 OpenAI / Azure OpenAI | DeepSeek（任何 OpenAI 兼容端点），带响应缓存、预算熔断、峰谷定价 |
| 论文从哪来 | Paper Graph 展示文献空间，检索依赖外部配置 | arXiv + OpenAlex 双源检索 → 去重 → BM25 + LLM 精排 → 逐篇结构化抽取；另有本地 PDF 精读 |
| 功能范围 | RQ 流程编辑器、论文图、AI 思考 | 上述三项 + 研究空白挖掘（4 策略）、进展扫描（时间窗）、Elo 两两盲评、提案生成、期刊偏好 |
| 部署 | docker-compose（dev server） | 单容器生产模式，或**完全不用 Docker** 的原生模式（自动建 venv） |
| 数据 | 会话与文献依赖外部服务 | 全部落本地 SQLite，可离线，数据不出本机 |
| 成本 | 未做控制 | 缓存 + thinking 开关 + 模型分级 + 日预算熔断 + mock 模式，全流程约 ¥3~5 |

**保留的思想**（这部分是 CoQuest 的贡献）：

- **问题树是主数据结构** —— 每个节点是一个问题 / 假设 / 排除 / 场景 / 做法，而不是聊天记录
- **AI 思考外显** —— 不只给结论，还给出「为什么这么拆、打算怎么引导、可能哪里不对」
- **证据联动** —— 节点挂真实论文 id，点开能跳转，编造的引用直接丢弃

**换掉的部分**：

- **技术栈整体重写** —— AutoGPT 分支换成自写的状态机 + 结构化抽取；Pinecone/Redis 换成 SQLite + FTS5，
  少两个要单独跑的服务
- **从「实验工具」变成「生产工具」** —— 补上本地论文精读、空白挖掘、时间窗扫描、Elo 排序、提案导出
- **加了成本工程和离线能力** —— 原项目假设你有 OpenAI 额度；这里按「一个月几十块」来设计
